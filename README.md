# 铁路运单草单审核助手

面向已适配的中俄国际铁路运单版式的本地桌面工具。程序读取 PDF 第 1 页，按页面位置提取指定栏位，再检查用户逐行填写的必含文字或编号，支持单份审核和 ZIP 批量审核。

项目使用 Python、PySide6 和 QtPdf。文件读取、文字提取和规则比对均在本机完成，运行时不依赖云服务或 AI API。

## 功能概览

| 功能 | 当前行为 |
| --- | --- |
| 单份审核 | 检查选中的单个 PDF；未选择单个 PDF 时，检查 ZIP 内第一份 PDF。 |
| ZIP 批量审核 | 在后台线程按 ZIP 条目顺序逐份检查，显示进度；单份文件失败后继续处理其他文件。 |
| 栏位选择 | 支持第 3、4、23、25 栏；每栏可独立启用，第 25 栏默认停用。 |
| 文件与文字预览 | 查看 ZIP 的 PDF 清单、某份 PDF 的第一页原始文字，以及已启用栏位的提取原文。 |
| 逐文件报告 | 显示匹配情况、未匹配要求和栏位原文；双击批量清单中的文件行查看详情。 |
| 批次汇总与取消 | 汇总匹配、需复核、失败及未处理数量；支持在当前文件处理完成后取消。 |

### 支持的审核栏位

| 栏号 | 定位标题 | 默认状态 |
| --- | --- | --- |
| 3 | 发货人声明 | 启用 |
| 4 | 收货人 | 启用 |
| 23 | 运送费用的支付 | 启用 |
| 25 | 与承运人无关的信息 | 停用 |

“全部匹配”表示当前启用栏的必含文字均已找到。结果用于辅助人工核对，不代表整份运单的全部业务要求均已满足。

## 安装与启动

### 运行环境

- 需要可运行桌面界面的 Python 环境，建议使用 64 位 Python。
- 固定依赖为 `PySide6==6.10.1`，其安装元数据声明的 Python 范围为 `>=3.9,<3.15`。
- 当前本机核验环境为 Windows 64 位、Python 3.14.10、PySide6 6.10.1；其他系统和 Python 版本尚未在本项目中验证。
- PDF 读取使用 PySide6 自带的 `QtPdf`，无需额外安装 PDF 解析库。

### Windows PowerShell 快速开始

逐行执行以下命令：

```powershell
git clone https://github.com/fengqiao628-blip/Russian-Lab.git
cd .\Russian-Lab\railway_waybill_helper
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

如果已下载或克隆项目，直接进入其中的 `railway_waybill_helper` 目录，再创建虚拟环境、安装依赖并启动。已有可用虚拟环境时，直接执行最后一条启动命令。

这些命令直接调用虚拟环境中的 Python，无需运行 `Activate.ps1`。虚拟环境需要在本机创建，不应直接复制其他电脑上的 `.venv`。更新源码后，请关闭旧窗口再重新启动。

## 使用流程

1. 点击“选择 PDF”或“选择 ZIP”指定文件。ZIP 可直接读取，无需预先解压。
2. 选择需要审核的栏位。至少启用一栏，每个启用栏至少填写一条非空要求；停用栏不参与比对，也不会清空已输入的内容。
3. 首次使用某份样本时，点击“预览各栏提取内容”，对照原 PDF 确认提取范围。需要排查文字层时，可使用“预览 PDF 第一页文字”。
4. 在各栏输入框中逐行填写该栏必须包含的原文或编号。下例仅演示输入方式，需要替换成实际文件中的内容：

   ```text
   示例收货人名称
   1234567890
   ```

5. 点击“开始审核（单份）”或“开始 ZIP 批量审核”。批量运行期间，文件选择和要求输入会暂时锁定，整批使用启动时的同一套要求。
6. 查看结果。批量任务中可双击文件行查看“审核详情”，点击“查看批次汇总”返回汇总报告。需要保留报告时，请在详情区选中复制。

### 各按钮使用的文件来源

| 操作 | 同时选择 PDF 和 ZIP 时的行为 |
| --- | --- |
| 开始审核（单份） | 优先使用单个 PDF；只有未选择单个 PDF 时才读取 ZIP 第一份 PDF。 |
| 预览 PDF 第一页文字 | 与单份审核相同。 |
| 预览各栏提取内容 | 与单份审核相同，仅提取已启用栏。 |
| 开始 ZIP 批量审核 | 始终使用 ZIP 路径，检查其中每份 PDF 的第 1 页。 |
| 查看 ZIP 文件清单 | 使用 ZIP 路径列出 PDF 条目，并展示当前要求；不执行审核。 |

ZIP 的“第一份”以压缩包内部条目顺序为准，不按文件名排序。子文件夹中的 PDF 会被包含，扩展名匹配不区分大小写；嵌套 ZIP 不会继续展开。同名 PDF 条目在批量任务中会分别读取、分别计数。

## 匹配规则

每个非空行是一条独立要求，同一栏的所有要求都需要在该栏原文中出现。允许原文包含额外内容，也不要求各条要求按输入顺序出现。

比对前会进行 Unicode NFKC 规范化、大小写折叠，并将换行、制表符和连续空白合并为一个空格。要求按普通文字处理，括号、加号等不作为正则表达式。

| 原文与要求示例 | 结果与原因 |
| --- | --- |
| 原文 `ABC 123`，要求 `abc １２３` | 匹配：统一大小写和全角数字。 |
| 原文中 `ABC` 与 `123` 之间为换行，要求 `ABC 123` | 匹配：换行按空格处理。 |
| 原文 `123456`，要求 `123` | 不匹配：要求以数字开头或结尾时，检查相应边界，避免命中更长数字串的一部分。 |
| 原文 `123 456`，要求 `123456` | 不匹配：不会删除编号中间的空格并拼接数字。 |
| 俄文字母 `ООО` 与拉丁字母 `OOO` | 不会自动视为相同，即使外形相似。 |
| 原文 `A, B`，要求 `A,B` | 不匹配：标点后空格的有无仍会造成差异。 |

应填写要出现的具体文字，不能用“请判断收货人是否正确”等自然语言代替规则。编号匹配也不包含编号真实性、校验位或业务有效性判断。

## 如何理解结果

| 批量清单结果 | 含义与后续操作 |
| --- | --- |
| 全部匹配 | 所有启用栏的本次要求均已找到；可查看原文核对。 |
| 需复核 | 存在未匹配要求，或已定位的栏位未提取到文字；查看详情并对照原 PDF。 |
| 读取或提取失败 | 无法读取文件或可靠定位栏位，没有有效比对结论；详情会显示原因。 |

批次汇总另外显示总数、已处理数和未处理数，以及启动时使用的要求。点击“取消批量审核”后，当前文件结束才会停止，已完成结果保留；再次开始会从头处理整个 ZIP。批量运行时关闭窗口，也会先等待当前文件结束。

## 适用范围与限制

- **检查范围**：每份 PDF 仅处理第 1 页，仅支持上述四个审核栏位。
- **版式要求**：提取器依赖当前中俄运单的页面比例、固定标题及其相对位置。即使只启用一个审核栏，也需要第 3、4、5、8、23、24、25、26 栏的定位标题符合模板。
- **文字来源**：依赖 PDF 自带文字层，尚未接入 OCR；扫描图片、文字编码异常或其他模板可能无法提取。
- **密码文件**：不提供 ZIP 密码或 PDF 打开密码输入；需要密码的文件无法直接审核。
- **结果保存**：要求与结果只保存在当前窗口内，关闭后不保留；尚无规则模板保存、数据库、Excel/PDF 导出或断点续查功能。
- **原文件**：读取与提取均不修改原 PDF；ZIP 内的 PDF 读取到内存，不解压到磁盘。

仓库未附带用于业务验收的运单样本。原开发记录中的 `55草单.zip` 是本地历史样本，不能直接用于复现所有电脑上的测试。

## 项目结构与实现

```text
Russian-Lab/
├── README.md                         # 仓库首页：功能、安装、使用和限制
├── railway_waybill_helper/
│   ├── main.py                       # QApplication 与程序入口
│   ├── main_window.py                # 桌面界面、输入校验、预览与结果展示
│   ├── file_reader.py                # ZIP 清单与单份 PDF 数据读取
│   ├── pdf_reader.py                 # QtPdf 文档生命周期与第一页文字读取
│   ├── pdf_text_positions.py         # 显示文字下标与 PDF 内部位置校正
│   ├── field_extractor.py            # 标题定位、栏位矩形与阅读顺序重建
│   ├── reviewer.py                   # 文字规范化、逐行匹配与单份报告
│   ├── batch_review.py               # QThread 批量任务、进度与批次报告
│   ├── requirements.txt              # 固定依赖
│   ├── .gitignore                    # 忽略虚拟环境与 Python 缓存
│   └── README.md                     # 操作与实现细节、历史开发记录
├── railway_waybill_helper_source.zip # 历史源码归档，日常开发以源码目录为准
└── 界面预览.png                        # 早期界面截图，当前功能以代码为准
```

数据处理顺序为：读取 PDF 字节 → QtPdf 打开第一页 → 校验标题及位置 → 按栏位筛选文字 → 规范化并比对要求 → 生成报告。

`PdfTextLocator` 会核对显示文字与 PDF 内部字符位置，出现特殊字符偏移时再进行映射校正，无法可靠对应时报告失败。`BatchReviewWorker` 在一个后台线程中顺序处理文件，通过信号向主窗口传递结果；它不会同时并行解析多份 PDF。

更详细的函数说明与历史样本记录见[源码目录 README](railway_waybill_helper/README.md)。

## 验证与排错

### 建议的人工验证

准备一份符合模板且含有文字层的 PDF，以及包含多份样本的 ZIP，然后依次验证：

1. 整页预览能显示文字，栏位预览与原 PDF 对应。
2. 填入已存在的文字得到匹配；改动某个编号的一位后，报告列出未匹配要求与原文。
3. 启用栏留空会阻止审核；停用后该栏不参与检查。
4. 同时选择 PDF 和 ZIP，确认单份按钮与批量按钮分别使用上表中的来源。
5. 批量任务完成后，已处理数等于匹配、需复核和失败数之和，总数等于已处理数与未处理数之和。
6. 在含多份文件的批量任务尚未结束时取消，确认当前文件结束后停止并保留已完成记录；某份文件失败时，后续文件仍会继续处理。

### 常见问题

| 现象 | 排查方式 |
| --- | --- |
| `No module named 'PySide6'` | 使用同一个 `.venv\Scripts\python.exe` 安装依赖并启动程序。 |
| 找不到 `main_window` 等项目模块 | 进入 `railway_waybill_helper` 目录，并保持源码文件位于同一目录。 |
| 未找到栏标题、标题位置不符或页面比例不符 | 检查是否为已适配的中俄运单模板，以及 PDF 是否具有可读取文字层。 |
| 第 25 栏未提取或未审核 | 默认停用，需要先勾选；审核时还需填写至少一条要求。 |
| 报告出现未匹配项 | 对照提取原文检查数字、字母、标点、空白与栏位范围。 |
| ZIP 中没有找到 PDF | 检查文件是否位于 ZIP 的目录或子目录中；嵌套 ZIP 内的文件不会列入。 |
| 取消或关闭后仍在处理 | 协作取消会等待当前文件完成，不会立即强行中断。 |
| 更新后仍显示旧界面 | 关闭旧助手窗口，确认目录正确后重新运行 `main.py`。 |

反馈问题时，请提供操作步骤、Python/PySide6 版本及完整错误或报告；如需提供样本，请先处理其中的业务敏感信息。
