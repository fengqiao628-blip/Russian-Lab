### 新增 pdf_text_positions.py：这次错误的原因和修复

第38份样本包含 3399 个 PDF 内部字符位置，但 `getAllText().text()` 得到的字符串长度为 3398。旧定位代码直接使用显示字符串的下标，一旦遇到这种长度差异，后续词的位置就可能错位。

`PdfTextLocator` 专门处理这两套编号：

1. 保存完整显示文字，以及 `getAllText().endIndex()` 给出的内部字符边界。
2. 正常词直接定位，并核对取回的文字是否与目标词完全相同。
3. 发现不一致时，读取不同长度的 PDF 文字前缀，用二分查找确定目标词真正的内部起止边界。
4. 核对前缀和目标词都一致后，才接受该位置，并缓存后续位置的偏移。
5. 内部范围与可见文字长度不一致时，补入真实末字符的矩形，避免范围矩形截掉词尾。
6. 校正后的短词若返回空矩形，只加入相邻空白重新定位，并核对完整上下文，避免单字母或标点被漏掉。提取结果中仍只保留目标词。

二分查找的意思是每次把候选区间缩小一半，无需逐个位置尝试。缓存让正常文件继续使用直接定位，只在必要时执行校正。

`field_extractor.py` 改为调用 `locator.rectangle(start, end)` 获取坐标，栏标题校验、范围筛选和审核规则保持原有逻辑。索引仍无法核对时，继续报告提取失败，而不会产生不可靠的匹配结果。修复只转换读取时的索引，原 PDF 不会被改写，也不需要安装新库。

参考：[Qt 6.10.1 的 QPdfDocument 实现](https://raw.githubusercontent.com/qt/qtwebengine/v6.10.1/src/pdf/qpdfdocument.cpp)。

### batch_review.py：批量任务怎么运行

`BatchReviewWorker(QThread)` 把较长的 ZIP 检查放到后台，主窗口可以继续响应操作。它按压缩包顺序逐份执行原有的“读取 PDF → 提取启用栏 → 比对要求”，不是同时打开多个 PDF。

- `progress` 信号发送已处理数量、总数量和当前文件名。
- `item_ready` 信号发送一份文件的结果。
- `completed` 信号发送批次汇总和启动时的审核要求。
- 窗口中的 `on_batch_progress()`、`on_batch_item()` 等槽函数负责更新界面。后台线程不直接操作输入框、表格和进度条。

任务启动时会复制审核要求，窗口也会暂时停用文件选择、要求输入和其他 PDF 操作。这样一批文件始终使用同一套规则，当前运行中的 PDF 文档也不会被界面线程共享。

每份 PDF 都有独立的 `try/except`：某一份损坏、需要密码或版式不匹配时，记录为失败，再继续下一份。整个 ZIP 无法打开或没有 PDF 时，显示任务错误。

| 文件结果 | 含义 |
| --- | --- |
| 全部匹配 | 该文件所有启用栏的必含文字规则都匹配 |
| 需复核 | 有未匹配要求，或某栏没有提取到文字 |
| 读取或提取失败 | 未能完成该文件的读取或栏位定位，详情中有错误原因 |

取消采用 `requestInterruption()` 发出请求，后台在每份文件之间检查 `isInterruptionRequested()`。点击取消后，当前 PDF 处理结束才会停止；已完成结果保留，剩余文件标为未处理。再次开始会从整个 ZIP 重新检查，不是断点续查。

关闭运行中的窗口也先发出取消请求，等当前文件和后台线程结束后再关闭，避免销毁仍在运行的线程。

参考：[Qt 官方 QThread 文档](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QThread.html)。

### reviewer.py：怎样检查必含文字

这个文件只处理文字，不依赖窗口，也不需要新库。它有四个小函数：

- `normalize_text()`：使用 Python 自带的 `unicodedata` 统一兼容字符（如全角数字），用 `casefold()` 统一大小写，把连续空白、换行、制表符折叠为一个空格。
- `split_requirements()`：把输入按行拆开，跳过空白行。
- `compare_field()`：逐条检查某一栏的原文是否包含要求，返回状态、匹配项和未匹配项。
- `build_review_report()`：汇总启用栏的结果，整理成下方结果区的文字报告。

关键代码是：

```python
pattern = re.escape(expected)
if expected[0].isdigit():
    pattern = r"(?<!\d)" + pattern
if expected[-1].isdigit():
    pattern += r"(?!\d)"
```

`re.escape()` 让括号、加号等按普通文字处理。两侧的数字检查防止把 `123` 作为更长数字串 `1234` 的一部分判定为匹配。这不是证件号码或企业编号的有效性校验。

匹配允许本栏包含额外内容，各行要求顺序不限。它不理解“请检查收货人是否正确”这类自然语言，应直接填写要出现的原文或编号。

规则会保留具体数字、不同字母和标点差异。例如俄文 `ООО` 与外形相似的英文 `OOO` 不会自动视为相同；逗号后无空格与有空格也可能导致整句未匹配。换行按空格处理，不会把 `123 456` 拼接成 `123456`。因此“未匹配”需要结合提取原文核对，不能直接等同于业务错误。

启用但未填写要求的栏会阻止开始审核；未提取到文字不会被当作匹配。停用栏不参与检查，第25栏默认停用。

参考：[Python 官方 Unicode 规范化说明](https://docs.python.org/3.14/library/unicodedata.html#unicodedata.normalize)。

### field_extractor.py：按页面位置提取各栏

PDF 文字的存储顺序不一定是阅读顺序。在本次样本中，全部栏标题先出现在整页文字里，实际内容在后面。直接用“第3栏标题到第4栏标题”切字符串，会取错内容。

新函数 `extract_review_fields(pdf_data, field_numbers)` 按下面顺序工作：

1. 找到第3、4、5、8、23、24、25、26栏的标题。
2. 使用 `getSelectionAtIndex()` 和 `boundingRectangle()` 取得标题在第 1 页上的坐标。
3. 检查页面比例和标题的大致位置是否符合当前样本版式。定位不可靠时会显示原因。
4. 根据邻近栏标题计算目标栏的矩形范围。
5. 取得各词的位置，按词的中心点是否落入矩形筛选，再按从上到下、从左到右的顺序组成各栏文字。

| 栏号 | 内容区域的上下边界 |
| --- | --- |
| 第3栏 | 第3栏标题下方，到第8栏标题上方 |
| 第4栏 | 第4栏标题下方，到第5栏标题上方 |
| 第23栏 | 第23栏标题下方，到第24栏标题上方 |
| 第25栏 | 第25栏完整双语标题下方，到第26栏标题上方 |

页面坐标的原点在左上角，向右是 x 增大，向下是 y 增大。`QRectF(left, top, width, height)` 表示一个矩形；`area.contains(rectangle.center())` 判断一个词是否属于该栏。

这是针对本批次中俄国际货协运单的规则。其他模板、扫描件、标题改写或布局变化，可能需要另行适配。即使版式检查通过，也应先对照原 PDF 核对提取范围。提取函数每次只处理一份 PDF 的第 1 页；单份模式调用一次，批量模式对 ZIP 内各份 PDF 逐一调用。

参考：[Qt 官方 QPdfSelection 文档](https://doc.qt.io/qtforpython-6/PySide6/QtPdf/QPdfSelection.html)。

### pdf_reader.py：管理文档和提取整页文字

这个文件使用当前已安装的 `PySide6.QtPdf`，本次无需安装新库。

```python
document.load(buffer)
page_count = document.pageCount()
text = document.getAllText(0).text().replace("\r\n", "\n").strip()
```

`QBuffer` 把内存里的 PDF 数据提供给 Qt；`QPdfDocument` 打开文档；`pageCount()` 取得总页数；`getAllText(0)` 取得第 1 页的文字，因为程序里的页码从 0 开始。`strip()` 去掉首尾空白，最后返回总页数和文字。

PDF 组件可能返回 Windows 的 `\r\n` 换行，而文本框显示为 `\n`。统一换行格式后，字符统计与预览内容一致，后续处理也更容易。本操作只处理内存中的字符串，不修改原 PDF。

函数需要在已启动的 Qt 应用里调用。新增的 `open_pdf_document()` 把打开和关闭封装在一起：`with open_pdf_document(data) as document:` 在进入时打开 PDF，在离开时自动关闭文档和缓冲区。这让整页预览和各栏提取可以共用同一套错误处理。

某些 PDF 带有加密标记，但可直接打开；能否读取以文档实际加载结果为准。真正需要打开密码的 PDF 会显示提示，本步尚未加入密码输入功能。

参考：[Qt 官方 QPdfDocument 文档](https://doc.qt.io/qtforpython-6/PySide6/QtPdf/QPdfDocument.html)。

### 保留的 ZIP 清单函数怎么理解

`list_pdf_files(zip_path)` 接收 ZIP 的路径，返回文件名列表。

```python
from zipfile import ZipFile

with ZipFile(zip_path, "r") as archive:
    for entry in archive.infolist():
        if entry.is_dir():
            continue
        if entry.filename.lower().endswith(".pdf"):
            pdf_names.append(entry.filename)
```

- `zipfile` 是 Python 自带模块，无需 pip 安装。
- `ZipFile(..., "r")` 以只读方式打开压缩包。
- `with` 保证函数结束或出错时关闭文件。
- `infolist()` 读取 ZIP 的目录条目。这一步不解压，也不读取 PDF 正文。
- `is_dir()` 判断条目是否为文件夹，`continue` 跳过文件夹。
- `lower().endswith(".pdf")` 同时识别 `.pdf`、`.PDF` 等大小写形式。
- `append()` 把找到的文件名加入列表，最后通过 `return` 返回给窗口。

子文件夹里的 PDF 会包含在清单中，并显示完整的 ZIP 内部路径。其他文件会被跳过；如果 ZIP 里还有 ZIP，当前不会继续打开里面那一层。清单按压缩包内的条目计数，尚未验证文件内容是否为有效 PDF。

参考：[Python 官方 zipfile 文档](https://docs.python.org/3.14/library/zipfile.html)。

### main_window.py：收集要求并调用检查函数

`collect_requirements()` 是单份和批量共用的要求校验。`start_review()` 继续负责单份检查，校验通过后依次执行：

```python
source, data = load_preview_pdf(pdf_path, zip_path)
fields = extract_review_fields(data, requirements.keys())
report = build_review_report(source, scope, fields, requirements)
self.results_text.setPlainText(report)
```

四个输入框是“期望要求”，`fields` 是 PDF 中的“实际原文”，两者分别保存。`requirements.keys()` 只包含勾选的栏号，停用栏不会参加比对。

读取时出错或版式不匹配，会显示“未完成审核”以及原因，不会沿用上次结果或输出本次规则全部匹配。检查过程中按钮显示“正在审核”，结束或出错后恢复。

`start_batch_review()` 负责创建后台任务并连接信号。`set_batch_running()` 控制运行期间哪些输入可编辑；`on_batch_finished()` 在线程结束后恢复按钮；`closeEvent()` 在关闭窗口时处理未完成任务。

下方新增两个页签：“批量清单”显示逐文件结果；双击某一行后，“审核详情”显示这份文件的报告。“查看批次汇总”显示总数、匹配数、需复核数、失败数、未处理数，以及启动时使用的要求。

### 文件清单和预览功能继续保留

新增的“查看 ZIP 文件清单”按钮对应 `show_file_list()`，在要求预览之前调用：

```python
pdf_names = list_pdf_files(zip_path)
lines.append(f"ZIP 中找到 {len(pdf_names)} 个 PDF：")
for index, name in enumerate(pdf_names, start=1):
    lines.append(f"{index}. {name}")
```

`len()` 计算数量，`enumerate(..., start=1)` 给文件从 1 开始编号，`setPlainText()` 把拼好的文字显示在结果区。

调用被放在 `try/except` 中。ZIP 损坏、文件被移动或没有读取权限时，窗口会说明错误原因，方便你理解问题。

新增的 `preview_pdf_text()` 先调用 `load_preview_pdf()`，再调用 `read_first_page()`。成功时用 `QDialog` 打开独立窗口，其中 `QPlainTextEdit` 为只读，可滚动、选中和复制。关闭预览后回到原来的主窗口；审核要求不会因此被清空。

`preview_field_contents()` 读取主窗口里哪些复选框被勾选，只提取这些栏位。预览窗口分四栏展示 PDF 的实际内容，停用栏显示“本次未提取”。第25栏默认停用，勾选后再点击按钮才会提取。计算需要短暂等待时，按钮显示“正在提取”。

这时 `read_first_page()` 返回的两个值会被拆开接收：`page_count, text = read_first_page(data)`，与文件选择框返回路径和过滤器的写法类似。

第3、4、23栏仍默认启用，第25栏默认停用。停用不会清空已填写内容；清单后面仍会显示启用栏的要求预览。

## 3. 怎样验证新功能

1. 先关闭预览窗口，再关闭旧助手主窗口；用原来的命令重新运行。
2. 顶部应显示“第七步：ZIP 批量审核（文字定位修复）”。
3. 选择 `55草单.zip`。填写下文的测试要求，启用第3、4、23栏，第25栏保持停用。
4. 点击“开始 ZIP 批量审核”，进度会显示已处理数量和当前文件名。55 份文件可能需要几分钟。
5. 完成后检查“批量清单”是否逐项列出全部文件，核对匹配、需复核、失败和未处理数量。
6. 双击一行查看该文件详情；点击“查看批次汇总”查看整体报告。

## 4. 出错时先看原因

| 现象 | 原因和处理 |
| --- | --- |
| 顶部仍显示“第一阶段” | 旧窗口还在运行，或启动了另一份源码。关闭旧窗口，在本说明的 D 盘项目目录重新启动。 |
| 顶部仍显示“第二步”到“第六步” | 仍在运行更新前的窗口，关闭助手后重新启动。 |
| `No module named 'file_reader'` | 新增的 `file_reader.py` 没有放在 `main_window.py` 同一文件夹里。 |
| `No module named 'pdf_reader'` | 新增的 `pdf_reader.py` 没有放在 `main_window.py` 同一文件夹里。 |
| `No module named 'field_extractor'` | 新增的 `field_extractor.py` 没有放在 `main_window.py` 同一文件夹里。 |
| `No module named 'reviewer'` | 新增的 `reviewer.py` 没有放在 `main_window.py` 同一文件夹里。 |
| `No module named 'batch_review'` | 新增的 `batch_review.py` 没有放在 `main_window.py` 同一文件夹里。 |
| `No module named 'pdf_text_positions'` | 新增的 `pdf_text_positions.py` 没有与其他源码文件放在同一文件夹里。 |
| 批量显示“读取或提取失败” | 双击该行查看具体原因；该文件没有有效检查结论，其他文件会继续处理。 |
| 点击取消后仍在处理 | 当前文件完成后才会停止，等待任务显示已取消。 |
| 按钮和要求输入变灰 | 批量运行期间固定输入，完成或取消后自动恢复。 |
| 启用栏尚未填写要求 | 每个启用栏至少写一条必含文字。暂无要求的栏可以取消勾选。 |
| 存在未匹配项 | 这条要求没有在对应栏提取原文里找到。检查数字、字母、标点、空格以及提取范围；它可能是实际内容差异，也可能是格式或提取问题。 |
| 未找到栏标题、标题位置不符、页面比例不符 | 当前文档与已适配的中俄运单版式不一致，或没有可读取文字。先对照原文件，不应把这种情况当作审核通过。 |
| 栏位内容为空 | 定位范围内没有提取到文字，可能确实空白，也可能是扫描内容或编码问题，需人工检查。 |
| 第25栏没有提取 | 检查主窗口第25栏复选框是否启用。 |
| PDF 需要打开密码 | 该文档确实需要密码才能打开。本步尚未提供密码输入功能，可先选一份能直接打开的样本继续验证。 |
| 第一页没有提取到文字 | 可能是扫描图片、空白页或文字编码不受支持，当前尚未接入 OCR。 |
| 提示先选择文件 | 当前既没有选择 PDF，也没有选择 ZIP。 |
| ZIP 中找到 0 个 PDF | ZIP 目录里没有 `.pdf` 文件。检查是否选错压缩包，或 PDF 实际在另一个 ZIP 内。 |
| 文件不是有效 ZIP，或目录已损坏 | 文件格式与扩展名不符，或压缩包损坏。先确认能用资源管理器或压缩软件打开。 |
| 无法访问文件 | 选择后文件可能被移动、删除，或读取权限不足。结果区会显示系统返回的详细原因。 |
| 文件名编码或格式暂不支持 | 压缩包目录使用了无法识别的编码或 ZIP 特性，可重新打包后再试。 |
| `No module named 'PySide6'` | 安装和运行可能使用了不同的 Python。始终使用项目的 `.venv\Scripts\python.exe`。 |
| 窗口打开期间没有新的 PowerShell 提示符 | 这是程序持续运行的正常状态，关闭助手窗口后才会重新出现提示符。 |

遇到问题时，先保留完整报错、执行的命令和结果区文字，便于判断是在启动、文件读取还是界面展示时失败。

## 5. 在其他电脑上首次安装

本项目固定使用 `PySide6==6.10.1`，它的 Python 版本要求是 `>=3.9,<3.15`；本次在 Windows 64 位 Python 3.14.10 环境中检查。参考：[PySide6 官方发布信息](https://pypi.org/project/PySide6/6.10.1/)。

先安装可用的 64 位 Python，再克隆或下载源码，进入仓库内的 `railway_waybill_helper` 文件夹并打开 PowerShell（该文件夹包含 `main.py` 和 `requirements.txt`）。完整克隆命令见[仓库首页](../README.md)。下面三条命令逐条执行：

```powershell
python -m venv .venv
```

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

```powershell
.\.venv\Scripts\python.exe main.py
```

虚拟环境依赖本机的 Python，不应把其他电脑的 `.venv` 文件夹直接复制过来使用。源码包不包含虚拟环境。

本步骤没有 OCR、Excel 导出、数据库、网页框架或 AI API；没有自然语言理解、复杂业务判断、多页检查或断点续查。批量任务检查的是当前版式下每份 PDF 第1页的必含文字规则。
